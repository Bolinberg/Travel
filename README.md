# 自驾行程规划 App（MVP）

家庭自驾旅游计划工具。第一期只服务一个目标：**统筹 12 月墨尔本 → 阿德莱德的家庭自驾**——每天怎么走、住哪里、要花多少钱、出发前还差什么。

## 功能

## 规划流程

行程页最上面是四步进度条，点哪一步就跳到还没做完的那一天：

1. **每天去哪**：在时间线里点某一天 →「编辑」，只填地址——出发地默认是前一天的目的地，填上目的地和途经点即可。坐标（上地图）、真实道路里程、车程、油费、标题和交通方式（远处自动改自驾、同城短距离改步行）都会自动算好；改了目的地，第二天的出发地也跟着改并重算。需要手动改的放在「高级」里。
2. **住哪**：某一天 →「住宿」。① 点一下平台按钮（Booking.com 8 分以上按好评排序、Airbnb 房客推荐、Wotif 按评分、Tripadvisor、Google 地图），日期、人数和小孩年龄都已带上；② 看中了就把链接粘贴回来——自动认出平台和名字、加入并选定，连住几晚一起改，价格先按这处的估算计入花费；③ 订好后点「已订好」填实付总价，自动折算成每晚价格。没想好也可以直接「选推荐这家」。
3. **吃什么**：某一天 →「吃饭」。同样一键去 Tripadvisor、Google 地图（高分 / 适合带孩子）、OpenTable（带人数订位）找，粘贴链接就加入这天，价格知道了再填。当天餐饮按「每日标准」和「已选餐厅合计」中较大的算，不会重复。
4. **花多少**：「预订」页汇总总花费、分类和预算，住宿、渡轮、门票的「未订 / 已订 / 已付」，已选餐厅，以及按天的花费表（住宿 / 餐饮 / 油费 / 门票）。

小孩年龄在「设置 → 基本信息」里填，订房平台会按年龄算房型。

界面按「定方案 → 订 → 出发」分成 4 个标签（手机在底部，电脑在顶部），设置在右上角齿轮里：

| 页面 | 回答的问题 | 内容 |
| --- | --- | --- |
| 行程 | 这几天怎么走 | 顶部「下一步」：出发倒计时和最要紧的 3 件事（渡轮、未订住宿、门票）。下面是可展开的小地图和一天一行的时间线：日期、路线、车程色块（3 / 5 / 6 小时分色）、今晚住哪、订没订。点某一天，手机上从下往上拉出详情（电脑上就地展开、旁边地图聚焦这一天），分「安排 / 景点 / 住宿 / 吃饭」；「今晚住」可直接选推荐、去订、标记已订。右下角「✎ 改行程」用一句话改行程 |
| 方案 | 选哪一个 | 方案卡片（天数、总车程、最长一天、花费画成同比例条形），点卡片就改用那个方案；下面按「逐日 / 指标 / 地图」对比；一句话生成新方案、调整天数；历史版本折叠在最下面 |
| 预订 | 还要订什么、花多少 | 总花费、分类和预算；住宿按过夜地列出（附核实过的候选、去订链接）；渡轮、门票等每项「未订 → 已订 → 已付」点一下切换；油费、餐饮自动估算，其他零花可增删 |
| 准备 | 出发前和路上 | 出发倒计时 + 分组清单（出发前 / 行李 / 路上注意 / 阿德莱德 / 袋鼠岛），可自定义 |
| 设置（齿轮） | | 出发日期、人数、预算、车辆油耗与油价、餐饮标准；邀请家人一起编辑；AI 推荐；导出/导入 JSON |

数据默认保存在浏览器本地（localStorage）；部署后端后可开启「家庭同步」，多设备共用。

联网时 App 会在设备上调用以下免费服务（结果缓存）：OpenStreetMap 地图瓦片、OSRM 驾车路线、维基百科景点照片、Nominatim 地点坐标查询。离线时路线显示为虚线直连。

住宿和餐饮推荐整理自 2025–2026 年 Tripadvisor、Wanderlog、OpenTable 与各地官方旅游网站上仍在营业的商家；价格是 12 月旺季一家四口的估算，预订前请以官网为准。

## 用于其他行程

右上角「我的行程」可以管理多个行程：

- **新建 → 空白行程**：填出发地、目的地、天数、人数、预算，自动生成「出发 → 目的地停留 → 返程」骨架，查好坐标并按真实路线算出里程。之后在「行程」页逐天修改目的地、加途经景点。
- **新建 → 复制当前行程**：沿用路线和预算，清空预订/付款/勾选状态，适合同一路线再走一次。
- **新建 → 示例模板**：墨尔本 → 阿德莱德 9 天完整示例。
- 任意新地点点「全部定位」即可上地图（全球地名均可，英文更准）。
- 住宿/餐饮：每天都有 Booking、Tripadvisor、Google 地图搜索链接，看中的用「+ 自己添加」记下来。
- 导入别人导出的 JSON 会作为新行程加入，不会覆盖现有行程。

### 用一句话改行程（自然语言调整）

行程页右下角「✎ 改行程」，或「方案」页的输入框：直接写「最后一天直接回家」「在阿德莱德多住一天」「第 1 天别开那么久」等。
Claude 只改你提到的部分，未提到的日子（含预订、推荐、备注）原样保留，然后弹出对比预览：

- **应用到当前方案**：覆盖当前方案（应用前自动保存一份，可撤销，也可在「方案」页找回）；
- **另存为新方案**：作为方案 B / C / D… 加入方案卡片，便于并排比较。

在 Claude 里打开本页时直接使用 Claude（第一次会询问是否允许页面调用 Claude）；网页版需要在「设置 → AI 推荐」填写 API Key。

### 方案卡片与逐日对比

「方案」页顶部是方案卡片：每个方案的天数、总车程、最长一天、预计花费都画成同一比例的条形，车程超过 5 小时的天数单独提醒。点卡片就改用那个方案（当前的修改会自动存回原方案），「+ 新方案」用一句话生成新方案。
有两个以上方案时，下面可以按「逐日」（按天并排显示路线、车程分色和住宿地）、「指标」（里程、车程、花费等，最优项标绿）或「地图」对比。

### 调整天数（如 9 天 → 6 天）

在「行程」页顶部点 **调整天数**，输入目标天数，然后选：

- **智能调整**（无需联网）：缩短时反复合并「代价」最小的相邻两天（车程短、同城日优先，超过 6 小时重罚），被合并那天的终点变成途经点；延长时先拆分超过 5 小时的长途日，再在过夜最多的目的地加住一晚。
- **✨ AI 调整**：Claude 综合景点取舍、车程和孩子体力重新编排，可写额外要求（如「阿德莱德至少住 2 晚」）。

生成后先看 **对比**：天数/里程/驾驶时长/最长一天/预计花费/结束日期的前后变化，长途日和需要改订的已预订住宿警告，不再经过和新增的地点，新旧两张地图，以及逐日对照（每天标明 合并 / 拆分 / 新增 / 调整 / 不变，并列出来自原计划的哪几天）。**确认应用** 后才写入，行程页顶部可 **撤销**。原有的住宿、推荐和开销会尽量沿用到对应的新日期。

### 方案与历史 / 多方案对比

- **行程页直接切换方案**：行程里有 2 个以上备选方案（例如 A/B 路线对比）时，行程页顶部会出现方案按钮，点一下整个 App（行程、地图、费用、清单）就换成那个方案。切换前当前内容会存回它所属的方案，所以在各方案里做的修改都会保留；不属于任何方案的内容会先自动存档。
- 调整天数、AI 批量生成、恢复旧版本、删除某天之前会**自动保存**当前版本；也可以随时「保存当前为方案」，或在调整天数时把生成的方案「另存为方案」（不应用）。
- 「方案」页列出当前版本和全部历史/备选方案，可改名、删除、**采用**（采用前会再自动保存一次，随时能切回）。
- 勾选 2–4 个方案点「对比所选」：并排比较天数、里程、驾驶时长、最长一天、超 6 小时天数、预计花费/人均/每天、地点数、结束日期、过夜地（绿色为最优），逐日路线对照，以及每个方案的地图。
- 版本保存在行程里（最多 20 个，超出先删最旧的自动保存），导出 JSON 时一并带上，家人导入后也能看到各个方案。

### 交通方式与路线

- 每天可设主要交通方式（自驾 / 步行 / 骑行 / 公交火车电车 / 轮渡 / 飞机），也可以在编辑里「分段设置」，例如开车到市区再坐电车去 Glenelg。
- 自驾、步行、骑行按真实道路计算（OSRM：routing.openstreetmap.de 的 car/foot/bike，自驾失败回退 router.project-osrm.org，限流 + 缓存）；公交、轮渡没有免费路线服务，画示意线，飞机画大圆航线，均在线上和提示中标明「示意」。
- 部署了后端时，地图瓦片和路线**经由自己的后端代理**（`/api/map/tile`、`/api/map/route`，同源访问、服务端缓存，并按 OpenStreetMap 要求标明 User-Agent），其次才直连 OpenStreetMap / OSRM 公共服务（不用 CARTO：它现在需要 API Key，没有 Key 时返回带水印的图片）。
- 底图所有来源都加载失败时（常见于在聊天 / 文件 App 里直接预览 HTML，这类环境禁止联网），地图上会说明原因和解决办法。
- 地图用不同线型 + 图标区分交通方式并显示图例；获取失败的路段显示为虚线并可「重试」。地图页会用实际路线核对当天填写的里程/时间，不一致时可一键更新。
- 「途经点按顺路排序」自动重排途经点；AI 新增的景点会插入最顺路的位置。Google 导航链接使用当天的交通方式；油费只计算自驾的日子。

### ✨ AI 推荐

在「设置 → AI 推荐」填入自己的 [Anthropic API Key](https://console.anthropic.com/settings/keys)（可选填家庭偏好），然后：

- 每天展开「景点 · 住宿 · 餐饮」点 **✨ AI 生成推荐**，或在设置里 **为全部天生成**；
- Claude（默认 Claude Opus 5.5）会联网搜索，只推荐能确认仍在营业的商家，返回：沿途景点（坐标 + 中文介绍，自动加入地图和途经点）、当晚住宿 3 家（含估价，可一键填入）、午/晚餐餐厅；
- 结果去重后合并到当天，不会覆盖已有内容；每次显示搜索次数和估算费用（通常每天 US$0.1–0.5）。

实现见 `src/ai.ts`：浏览器直接调用 Anthropic Messages API（流式），使用 `web_search` 服务端工具 + 严格模式的 `submit_recommendations` 工具返回结构化结果，客户端再做校验；开启了服务端 refusal fallback。Key 只存在本机 localStorage，不随行程导出。若要给不方便自己申请 Key 的家人用，可以改为经由自己的后端代理转发（届时把 Key 放在服务端）。

新增内置模板：在 `src/defaultTrip.ts` 的 `TEMPLATES` 里加一项，地点坐标放在 `src/places.ts`，推荐放在 `src/guides.ts`。

## 家庭同步（多设备）

一人「创建家庭空间」，把邀请链接发给家人；家人打开链接、填个称呼就加入。之后大家看到和编辑的是同一份行程：

- 修改约 2 秒后上传；其他设备每 15 秒、切回 App、恢复联网时拉取。右上角 ☁️ 显示同步状态。
- **不会互相覆盖**：服务器按版本号做乐观并发控制。两人同时改了同一个行程时，以先上传的为准，另一台设备未上传的内容自动存进「方案」历史（标注「同步冲突」），随时可以对比或采用。
- 无需注册账号：邀请链接里的密钥就是凭证（服务器只存它的 SHA-256）。链接发错了可以「更换密钥」，旧链接和旧设备立即失效。
- 离线时照常使用，联网后自动补传。

后端代码在 `server/`（Hono + Node 22 自带的 SQLite），客户端在 `src/sync.ts`、`src/useSync.ts`、`src/SyncUI.tsx`。

## 部署

### 方案 A（推荐）：一个服务同时提供 App 和同步

后端也托管 App 页面，家人只需要打开同一个网址。需要一个能长期运行、有持久化磁盘的地方：

**Fly.io**（澳洲有悉尼机房）：

```bash
fly launch --no-deploy        # 按提示选择/修改 app 名称（fly.toml 已写好）
fly volumes create travel_data --size 1 --region syd
fly deploy
```

部署后访问 `https://<app 名称>.fly.dev`，在「设置 → 家庭同步」里服务器地址会自动填好，创建家庭空间即可。家庭用量很小，费用请以 Fly.io 官网为准。

**任意支持 Docker 的服务器 / NAS**：

```bash
docker build -t travel-planner .
docker run -d -p 8787:8787 -v travel-data:/data --name travel travel-planner
```

对外访问请配 HTTPS（例如放在 Caddy / Nginx 后面），浏览器才允许从 https 页面调用。

### 方案 B：App 放 GitHub Pages，后端放别处

GitHub Pages 只能托管静态页面，**不能运行后端**；同步仍需要按方案 A 部署一个后端。之后：

1. 仓库 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**（只需一次）。
2. （可选）**Settings → Secrets and variables → Actions → Variables** 新建 `SYNC_SERVER`，值为后端地址（如 `https://travel-planner-family.fly.dev`），页面里会自动填好服务器地址。
3. 推送到默认分支后 `.github/workflows/pages.yml` 自动构建并发布到 `https://<用户名>.github.io/<仓库名>/`。

后端必须是 https 地址（GitHub Pages 是 https，浏览器会拦截调用 http 的请求）。API 默认允许跨域（用 Bearer 密钥鉴权、不用 Cookie）；如需限制，设置环境变量 `CORS_ORIGIN=https://<用户名>.github.io`。

## 在 Claude 里打开

`npm run build:artifact -- <输出目录>` 会把 App 转成 Claude Artifact 页面（`scripts/build-artifact.mjs`），连同预算好的路线 `route-cache.json` 一起发布。Artifact 里不能访问外部网站，所以：

- 地图底图换成内置的澳洲东南部海岸线（Natural Earth 10m，`src/land-se-au.json`）；路线用预先算好的真实道路（`npm run build:routes` 重新生成）。
- 景点照片、AI 推荐、家庭同步、导出 JSON、打印在 Artifact 里不可用，请用网页版。
- 确认框默认通过、输入框使用默认名称（删除某天、采用旧方案前都会自动存档，可在「方案」里找回）。

## 开发

```bash
npm install
npm run dev      # 前端开发服务器
npm test         # 单元测试 + 同步服务端/客户端集成测试
npm run build    # 打包前端（dist/）和后端（dist-server/）
npm start        # 启动后端（同时托管 dist/），默认 http://localhost:8787
```

需要 Node.js 22.13 或以上（使用内置的 `node:sqlite`）。环境变量：`PORT`、`DB_PATH`（默认 `./data/travel.db`）、`HOST`、`CORS_ORIGIN`、`TILE_URL`（瓦片上游，默认 OpenStreetMap；家庭以外较大用量请换成商用瓦片服务）、`MAP_USER_AGENT`。
